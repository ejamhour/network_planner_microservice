# SDK 0.1.46 — Cache puro e features enriquecidas separados

`enrich_features()` agora lê `features.json` e grava `enriched_features.json`,
sem modificar o cache de extração. Treinamento, avaliação e inspeção dos
desvios leem o arquivo enriquecido; seus hashes de validade também se referem
a esse arquivo. Salvar um cache de uma sessão anterior não apaga observações.

Em `baseline.json`, `data` continua indicando o cache puro de entrada. O novo
campo opcional `enriched` indica a saída de enriquecimento. Quando omitido,
a saída é `enriched_features.json` na pasta do projeto. Arquivos distintos são
exigidos para cache, enriquecimento, medições, modelo e resultados.

Repetir o enriquecimento preserva observações existentes e usa as features
atuais do cache para as entradas correspondentes. Alterar uma observação
continua exigindo `replace=True`. A gravação da saída é atômica, após validação.
O arquivo enriquecido é um conjunto de dados derivado; atualizá-lo é uma ação
explícita. Atualizar apenas o cache não modifica esse conjunto ou seus relatórios.

Os notebooks E08 e E09 e suas receitas foram atualizados. As chamadas públicas
permanecem iguais. Receitas anteriores, sem `enriched`, usam o novo nome padrão:
não é preciso apagar pastas. Após atualizar SDK/notebooks, execute novamente
o enriquecimento antes do treinamento ou da avaliação.
