# SDK 0.1.52 — Revisão de reconfiguração

`InstalledNetworkProject.review_reconfiguration(layout="logical")` abre a topologia instalada para revisão. O usuário escolhe o modo do próximo clique: `link` retira somente o enlace; `subtree` retira também os enlaces descendentes. Cada seleção mantém seu modo. As sobreposições são consolidadas. O botão de sugestões seleciona somente a classificação `review_design`, incluindo as indicações sem medição, que continuam identificadas no painel de inspeção.

Enlaces removidos aparecem em vermelho tracejado. Rádios preservados sem acesso ao backbone aparecem em laranja; quando têm equipamento associado, mantêm o preenchimento roxo com contorno laranja. O diagnóstico e os caminhos do painel continuam sendo os da rede original. Nenhum planejamento é executado.

No modo subárvore, o usuário identifica explicitamente os rádios que são repetidores removíveis, no painel **Seleções e repetidores**. Também pode fornecer `repeater_devices=["site:d0", ...]` na chamada. Equipamentos associados são protegidos. Uma interface em outro trecho preservado impede a remoção do device inteiro. Ausência no inventário não prova que um rádio seja repetidor.

Depois de revisar o destaque, o usuário marca a confirmação e clica em **Confirmar e baixar reconfiguration.json**. Alterar a prévia exige nova confirmação. O download funciona no HTML independente e no iframe do notebook. Como a visualização é HTML local sem comunicação com o kernel, o navegador baixa o arquivo; o usuário deve salvá-lo na pasta do projeto ou enviá-lo pelo navegador de arquivos do Jupyter.

```python
review = project.review_reconfiguration(layout="logical")
```

Depois de colocar o arquivo no workspace:

```python
reconfiguration = project.load_reconfiguration(project.path / "reconfiguration.json")
```

O arquivo tem formato `cisei-network-reconfiguration`, versão 1. Contém confirmação, origem, solicitações por `link_id` e modo, identificação explícita de repetidores e impacto consolidado: enlaces preservados/removidos, interfaces da subárvore, devices/interfaces removidos, interfaces ainda conectadas, interfaces flutuantes e equipamentos protegidos. A origem identifica configuração, topologia e associações de equipamentos por SHA-256. A leitura recalcula todo o impacto e rejeita arquivo não confirmado, origem alterada ou impacto divergente.

`preview_reconfiguration(requests, repeater_devices=())` oferece o mesmo cálculo local sem confirmação nem gravação. A prévia não altera TOML, CSV, resultados, caches, modelo ou avaliação. A geração de um novo projeto a partir do arquivo revisado e as alterações no planejador são etapas posteriores; esta versão implementa apenas a revisão e o contrato de reconfiguração.

O notebook distribuído `e10_diagnostico.ipynb` inclui a revisão na seção 9, mantendo apenas chamadas ao SDK.
