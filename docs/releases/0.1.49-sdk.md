# SDK 0.1.49 — Candidatos opcionais e grafo avaliado Mesh

- O CSV aceita candidate como booleano de instância. No planejamento Mesh, equipamentos opcionais são selecionados automaticamente e filtrados por tecnologia/frequência dos endpoints, interface habilitada, can_relay e can_route. Perfis distintos da mesma tecnologia são aceitos; devices com várias tecnologias participam pela interface compatível. Mais de uma interface compatível por candidato requer desabilitar as alternativas ambíguas.
- plan_mesh_link aceita IDs de interfaces nos argumentos terminais, ou IDs de site quando inequívocos. O destino deve estar connected=true. Nenhum endpoint é promovido silenciosamente a acesso externo. pole_sites permanece como filtro explícito opcional para chamadas antigas; não é mais necessário no exemplo.
- show_mesh_candidates exibe o grafo dos enlaces efetivamente avaliados, seus custos e o caminho escolhido em laranja. O snapshot é salvo como mesh_candidates no resultado. expanded indica tentativa de buscar repetidores para aquele segmento; evaluated indica custo calculado; selected indica uso na solução.
- O resultado final inclui apenas as interfaces dos equipamentos escolhidos; os candidatos opcionais restantes não entram como nós sem serviço. Essa semântica é aplicada ao fluxo de planejamento Mesh; não altera a seleção dos demais planejadores.
- O exemplo exemple_4_Mesh_basic mostra os grafos avaliados e as soluções Copel–Guaíra e Copel–Itália, com flags explícitas e perfis mesh, Wi-SUN e duplo para demonstrar a filtragem.
