# SDK 0.1.47 — Classificação de enlaces e diagnóstico de caminhos

`InstalledNetworkProject.evaluate_links(rssi_threshold_dbm=...)` aplica o
modelo treinado da E08 a `enriched_features.json`. A classificação usa a mesma
função da E08: atendimento satisfatório, investigar instalação ou defeito,
medição satisfatória sem correção e revisar projeto. Não há novo treinamento
nem alteração da topologia ou dos caches.

O resultado é `evaluation.json`, mantendo o relatório da E08 e acrescentando
`installed_links`, `installed_categories` e hashes da topologia/configuração.
As conexões internas aparecem explicitamente, sem previsão ou RSSI fabricados.
Sem medição, features disponíveis permitem uma previsão: resultado insuficiente
indica revisão de projeto; previsão satisfatória continua marcada como sem
medição. Features insuficientes produzem dados insuficientes, não um diagnóstico
de defeito. O diagnóstico desta versão exige uma observação selecionada por
enlace; múltiplas amostras não são agregadas silenciosamente.

`show_topology(layout="logical" | "geographic", diagnosis=True)` preserva as
cores ao destacar o caminho. Usa verde, vermelho, azul e marrom, como a E08;
cabo é cinza tracejado. Os nós têm cor neutra. Clique em um nó para ver os
enlaces ascendentes, contagens de inspeção/revisão e valores previstos/medidos.
Clique em um enlace para sua descrição individual. Cada HTML é salvo como
`topology_<layout>_diagnosis.html`, sem substituir as vistas da topologia pura.

`diagnose_path(interface_id)` disponibiliza o mesmo diagnóstico em dados para
outros consumidores. Os hashes de modelo, conjunto enriquecido, topologia e
configuração são verificados antes da visualização ou consulta; alterações
exigem nova avaliação. O diagnóstico localiza trechos para investigação, sem
atribuir automaticamente uma causa física específica ou cruzar com aplicação.
