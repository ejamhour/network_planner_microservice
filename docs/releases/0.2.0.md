# Network microservice 0.2.0 — 2026-10-15

Includes notebook SDK 0.1.31. Build with:

```sh
docker build -f infra/Dockerfile -t network-planner-microservice:0.2.0 .
```

## Changes

- Independent features worker ownership using runtime IDs, pool numbers and worker indices; serialized pool registration, retained cleanup credentials and reported failures.
- Optional metric batches with accumulated results and atomic project cache checkpoints between requests. Failed requests or saves stop subsequent submission. Incomplete metrics cannot be solved through the planning endpoint.
- Configurable hub forwarding timeout (`PLANNING_WORKER_REQUEST_TIMEOUT`, default 600 seconds), distinct timeout/connection errors, closed proxy clients, and worker logs inherited by the container.
- Offline notebook HTML network views replace the default static plot, with endpoint selection, sector orientation guides, saved quality details and poor-quality highlighting. Explicit Matplotlib axes retain the legacy renderer. `save_path` writes standalone HTML beside results.
- Link inspection uses synchronized endpoint text and dropdown controls and a compact filtered list with local navigation.
- Example 2 imports 86 clients and five LTE 450 cells, with documented assumed antenna gains and an exploratory bidirectional link-budget metric. The metric is not a calibrated coverage model.

## Upgrade

Restart the network service after installing this code. Upgrade the notebook SDK to 0.1.31 from the service, restart the kernel, and refresh distributed notebooks if needed. Existing workspace project files are preserved by workspace preparation; copy reviewed project configuration changes explicitly. Existing feature caches keep format version 1 and can be reused with matching extraction parameters and source URLs.

`plot_network` now returns a NetworkView instead of Matplotlib Axes unless an explicit `ax` is supplied. Saved results without antenna metadata cannot draw sectors. Quality highlighting requires an embedded evaluation and its explicit rank threshold. Example 2 uses threshold 2 for the new metric; thresholds from its former obstruction score are not comparable.

Active job cancellation and recovery within failed batches are not part of this release. Page reloads do not cancel a running notebook kernel. Server-side metric file references are not implemented: custom specs are embedded in the example TOML, with an editable standalone reference file.
