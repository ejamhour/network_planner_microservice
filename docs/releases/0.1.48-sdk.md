# SDK 0.1.48 — Mesh com postes candidatos

- ScenarioSession.plan_mesh_link(src_site, dst_site, geo_base_url=...) chama POST /planning/scenarios/{scenario_id}/mesh/plan_link.
- scenario.toml mantém os perfis normais e uma seção [mesh] de parâmetros locais do SDK; nodes.csv contém extremos e locais candidatos. Um perfil por local descreve o equipamento proposto caso seja escolhido.
- [mesh]: pole_sites, max_repeaters, max_candidates, segment_threshold, search_heuristic (sector_band ou dual_cone), search_midpoint. Parâmetros explícitos na chamada sobrescrevem os do arquivo.
- A busca exige uma interface RF habilitada por posição, mesma tecnologia/frequência e custos finitos >=1. Usa o maior custo dos dois sentidos. Erros de features são propagados.
- O cenário de entrada é preservado; o resultado representa apenas o caminho proposto, com o destino como acesso externo do estudo. O limite de repetidores é respeitado na seleção final. mesh_search informa o caminho, custo e atendimento ao limite por segmento.
- show_mesh_link mostra resumo e mapa interativo. result.json contém a última proposta; os mapas são separados por par de extremos. features.json permanece um cache bruto, sem custos derivados.
- Novo exemplo distribuído: exemple_4_Mesh_basic.ipynb. A busca não configura antenas automaticamente nem incorpora as propostas a uma rede instalada.
